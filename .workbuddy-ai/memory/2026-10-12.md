## 修复：`./gowaf -config config.yaml` 报 flag not defined

### 根因
- 仓库根目录那份 `gowaf` 二进制是旧提交编译的，当时还没有 `-config` flag，
  所以运行时报 `flag provided but not defined: -config`。
- 代码层面 `-config` flag 早已存在（`main.go`）；用户诉求是让 `./gowaf`
  **无需显式传参** 也能加载 `config.yaml`。

### 改动（main.go）
- 配置文件加载逻辑改为：未传 `-config` 时，自动尝试当前目录的 `config.yaml`
  （存在则加载，解析失败回落 CLI 参数；不存在则纯 CLI 默认值，不报错）；
  显式 `-config <path>` 且文件不存在则直接退出。
- 重新 `go build -o gowaf .` 覆盖旧二进制。

### 验证
- `./gowaf -help` 确认 `-config` 已识别。
- 直接 `./gowaf`（不带 -config）启动，日志出现 `loaded config file path=config.yaml`，
  并随 config.yaml 里的 `mysql_dsn` 连上 myapp.users1（不再回 memory 模式）。

### 正确启动方式（已简化）
```bash
./gowaf                 # 自动加载当前目录 config.yaml（含 mysql_dsn → users1 持久化）
cd web && npm run dev   # 控制台 :3000
```
